01Game trees

Connect Four is a two-player, zero-sum, deterministic game of perfect information: both players see the whole board, there is no chance involved, and one player's gain is exactly the other's loss. Games like this can be described as a game tree. The root is the current position, each edge is a legal move (one of at most seven columns), and each child is the position that results. Leaves are positions where the game is over (a win, a loss or a full board), or positions where we choose to stop looking.

The branching factor b is the number of legal moves (at most 7 here) and the depth d is how many plies (single moves) ahead we look. A tree of depth d has about bd leaves: 74 = 2,401, 76 = 117,649 and 78 ≈ 5.8 million. The full game has about 4.5 trillion reachable positions and can last up to 42 plies, so the complete tree cannot be searched in real time. Every practical agent therefore searches only a small part of it.

{{ icon('info', 18) }}

Connect Four was solved in 1988, independently by James D. Allen and Victor Allis: with perfect play the first player wins by starting in the centre column. Our agents do not use that solution. They have to work things out by searching.

02Minimax

Minimax assumes that both players play optimally. The player to move (MAX) wants the highest value; the opponent (MIN) wants the lowest. Values are computed bottom-up: a leaf gets a score, a MIN node takes the minimum of its children, and a MAX node takes the maximum. The move at the root that leads to the best backed-up value is the one played.

function minimax(position, depth, maximizing): if depth = 0 or game over: return evaluate(position) if maximizing: return max(minimax(child, depth − 1, false) for child in children) else: return min(minimax(child, depth − 1, true) for child in children)

Proven wins are scored as +1,000,000 − depth and losses as −1,000,000 + depth. Subtracting the depth makes the agent prefer the fastest win and the slowest loss. Minimax is exact within its horizon, but it pays for that: it visits every one of the roughly bd positions, and anything beyond depth d is invisible to it (the horizon effect).

03Alpha-beta pruning

Alpha-beta returns exactly the same value and move as minimax, but it skips branches that cannot affect the result. It carries two bounds down the tree:

  • α (alpha): the best value MAX can already guarantee on the current path (starts at −∞).
  • β (beta): the best value MIN can already guarantee (starts at +∞).

As soon as α ≥ β at a node, the remaining children are cut off. One of the players already has a better option elsewhere, so the game will never reach this node.

function alphabeta(position, depth, α, β, maximizing): if depth = 0 or game over: return evaluate(position) if maximizing: value ← −∞ for child in ordered(children): value ← max(value, alphabeta(child, depth − 1, α, β, false)) α ← max(α, value) if α ≥ β: break # β cut-off return value else: # symmetric: minimise, update β, cut when α ≥ β

Why move ordering matters

How much gets pruned depends entirely on the order in which moves are tried. If the best move is searched first, the bounds become tight immediately and almost every other branch is cut after its first reply. Knuth and Moore (1975) showed that with perfect ordering alpha-beta examines about b⌈d/2⌉ + b⌊d/2⌋ − 1 leaves, or O(bd/2). In the same time it can search twice as deep as minimax. With random ordering the cost is roughly O(b3d/4), and with the worst ordering nothing is pruned at all.

In Connect Four, central columns belong to more potential lines of four, so trying moves centre-first (4, 3, 5, 2, 6, 1, 7) is a cheap and effective ordering. You can measure the effect in the Lab's pruning experiment. One side effect: in the Play page, the scores of non-chosen root moves are often only upper bounds (shown as "≤"). Pruning proved they cannot beat the best move, but it did not compute their exact value.

04Heuristic evaluation for Connect Four

When a depth-limited search stops before the game ends, it needs an evaluation function that estimates how good the position is. Our agents use window scoring. There are exactly 69 windows, sets of four aligned cells, on a 6×7 board: 24 horizontal, 21 vertical and 24 diagonal. A window that contains discs of both players can never become a four, so it is ignored. Every other window is scored by how many discs it holds:

The weights follow two principles. First, threats matter more than potential: three in a window with the fourth cell open is far more valuable than two. Second, the centre column is the most valuable, because more windows pass through it than through any other column. Opponent threes weigh slightly less than our own (−4 vs +5) because the side to move gets to act on threats first. Heuristic scores stay small (dozens), far below the ±1,000,000 used for proven wins. A forced win found by search therefore always outranks any heuristic estimate.

A heuristic is only an estimate. A position may score well and still contain a forced loss just beyond the search horizon. Searching deeper (alpha-beta) or using actual playouts instead of a formula (MCTS) are the two main ways around this.

05Monte Carlo Tree Search

MCTS replaces the hand-written evaluation function with statistics from simulated games. It grows an asymmetric tree one node at a time, spending more effort on the moves that look promising. Every iteration has four phases:

1SelectionFrom the root, repeatedly pick the child with the highest UCT score until reaching a node that still has untried moves.
2ExpansionAdd one untried move as a new child node.
3SimulationPlay random moves from the new node until the game ends (a "playout" or "rollout"). Our agent's playouts take an immediate win or block an immediate loss when one exists.
4BackpropagationWalk back up the path, adding 1 visit to each node and crediting the win (or ½ for a draw) to the player who made each move.

Selection uses the UCT rule (Upper Confidence bounds applied to Trees, Kocsis & Szepesvári 2006), which applies the UCB1 bandit formula at every node:

UCT(i) = wi / ni + c · √( ln N / ni ) wi = wins through child i · ni = visits of child i · N = visits of the parent · c = √2 in our agent

The first term is exploitation (the move's observed win rate). The second is exploration: it grows for moves that have been tried rarely compared with their siblings. Higher c explores more. After the budget of iterations is used up, the agent plays the most-visited root move, which is a more robust choice than the highest raw win rate. MCTS is an anytime algorithm (more iterations give better play) and needs no domain knowledge beyond the rules. As the number of iterations grows, UCT converges to the minimax move.

Its weakness is narrow tactics. If only one precise reply avoids a loss, random playouts may sample it too rarely to notice, especially with a small budget. This is the reverse of minimax's weakness: minimax sees short tactics perfectly but cannot see past its horizon.

07Which agent wins when

  • Random is the baseline. It loses to every other agent nearly every game, which shows how much even a little structure is worth.
  • Greedy never misses a one-move win or block, so it beats Random easily. It has no plans, though: any agent that sets up a double threat (two winning cells at once) beats it, because it can block only one.
  • Minimax is tactically perfect within its horizon, but its exponential cost limits it to shallow depths in real time. It is deterministic, so it plays the same game every time from the same position.
  • Alpha-beta chooses the same moves as minimax at the same depth, only faster. Given equal time it searches deeper, and that makes it the strongest agent here in sharp tactical positions.
  • MCTS shines when long-term structure matters more than short forcing lines, and it needs no evaluation function. With a small budget it can fall into narrow traps that a deep alpha-beta search sees immediately. With a large budget it becomes very strong but slower.
